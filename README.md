# Explore With Me (Микросервисная архитектура)

Сервис для поиска и публикации событий с **системой персональных рекомендаций в реальном времени**. Проект переведён из монолитной архитектуры в микросервисную с использованием Spring Cloud, Apache Kafka и gRPC.

## Стек технологий
- **Java 21**
- **Spring Boot 3.3.0** & **Spring Cloud** (Eureka, Gateway, Config Server, OpenFeign)
- **Spring Data JPA** (PostgreSQL)
- **Apache Kafka** & **Apache Avro** (для асинхронной потоковой обработки данных)
- **gRPC** (для высокопроизводительного синхронного межсервисного взаимодействия)
- **Docker & Docker Compose**
- **Postman** (для тестирования API)

## Архитектура проекта

Проект разделён на следующие микросервисы:

### Основные сервисы:
1. **`user-service`** — управление пользователями.
2. **`event-service`** — управление событиями и категориями (теперь запрашивает рейтинг через gRPC).
3. **`request-service`** — обработка заявок на участие (отправляет события REGISTER в Kafka).
4. **`compilation-service`** — подборки событий.
5. **`comment-service`** — комментарии к событиям.
6. **`stats-server`** — сбор и хранение базовой статистики просмотров.

### Сервисы рекомендательной системы (Этап 3-2):
7. **`collector-service`** — принимает действия пользователей (VIEW, REGISTER, LIKE) через gRPC и публикует их в Kafka в формате Avro.
8. **`aggregator-service`** — читает поток действий из Kafka и инкрементально рассчитывает косинусное сходство мероприятий, отправляя результаты в другой топик.
9. **`analyzer-service`** — сохраняет историю взаимодействий и матрицу сходств в PostgreSQL. Предоставляет gRPC API для получения рекомендаций на основе алгоритма K-ближайших соседей (KNN).

### Инфраструктура:
10. **`gateway-server`** — API Gateway (единая точка входа, маршрутизация).
11. **`config-server`** — централизованное управление конфигурациями.
12. **`discovery-server`** — Eureka Server (реестр микросервисов).
13. **`common`** — общий модуль с DTO, исключениями и утилитами.
14. **Базы данных**: `ewm-db` (основная) и `stats-db` (для аналитики и рекомендаций).

## Межсервисное взаимодействие
- **Service Discovery**: Все сервисы регистрируются в **Eureka Server**.
- **Синхронное взаимодействие**: Через **OpenFeign** (HTTP/REST) и **gRPC** (для высоконагруженных операций, таких как отправка действий и запрос рейтингов).
- **Асинхронное взаимодействие**: Через **Apache Kafka** с использованием бинарной сериализации **Apache Avro** для построения потокового конвейера данных (Event-Driven Architecture).
- **Маршрутизация**: Внешние запросы проходят через **Spring Cloud Gateway**.
- **Конфигурация**: Централизованно хранится в **Config Server**.

## Как работает система рекомендаций
1. Пользователь взаимодействует с событием (просмотр, лайк, заявка).
2. `event-service` или `request-service` отправляют действие через gRPC в `collector-service`.
3. `collector-service` сериализует данные в Avro и отправляет в топик Kafka `stats.user-actions.v1`.
4. `aggregator-service` читает топик, обновляет частные суммы и пересчитывает косинусное сходство между мероприятиями, отправляя результат в `stats.events-similarity.v1`.
5. `analyzer-service` читает оба топика и сохраняет актуальное состояние в PostgreSQL.
6. При запросе рекомендаций `analyzer-service` применяет алгоритм **K-ближайших соседей (KNN)**: находит похожие мероприятия, исключает уже просмотренные и предсказывает оценку на основе взвешенной суммы сходств.

## Как запустить проект

### Требования
- Docker Desktop
- Java 21 (для локальной сборки)
- Maven 3.8+

### Запуск через Docker Compose
1. Соберите проект (это создаст Docker-образы всех микросервисов):
   ```bash
   mvn clean install -DskipTests
2. Запустите инфраструктуру и сервисы:
   docker compose up -d --build
3. Важно: Подождите 40-60 секунд. Сервисам нужно время на инициализацию, подключение к Config Server, регистрацию в Eureka и выбор лидеров в Kafka.
4. Проверьте статус сервисов в панели Eureka: 
   http://localhost:8761 (все сервисы должны быть в статусе UP).
5. Основное API доступно через Gateway: 
   http://localhost:8080

### Локальный запуск (для разработки)
1. Запустите discovery-server и config-server.
2. Запустите нужные микросервисы через IntelliJ IDEA.

### Тестирование
В корне проекта находится коллекция Postman для тестирования API (Test Explore With Me - Feature).

#### Для запуска тестов:
1. Убедитесь, что все сервисы запущены.
2. Импортируйте коллекцию в Postman.
3. Запустите Runner и убедитесь, что все тесты проходят успешно (статус 200/201/409 в зависимости от сценария).
